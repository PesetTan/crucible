# AI notes

`AiNote.razor` displays saved editorial commentary as a compact, collapsed disclosure. It is used in the deck library, pilot profiles and saved assignments, setup, workshop, history, replays, results, and each field chart. Missing notes render nothing. Content is Razor-escaped text, never HTML.

Notes live in `data/simulator.sqlite` in `ai_notes`. A separate `AiNoteStore` is registered in UI, service, and combined modes so editorial writes do not require restarting the game service. It uses short SQLite transactions alongside the existing WAL database. Reads and signed append operations are available at `GET /api/v1/ai-notes?scope=deck&subject=<exact-deck-id>` and `POST /api/v1/ai-notes`. POST requires the host's existing `X-Instance-Token`, obtained from `/api/v1/session` on the same origin. These endpoints do not call a model.

A record contains `id`, `scope` (`page`, `deck`, `pilot`, `chart`, `run`), `subject`, `title`, `body`, `author`, `model`, `writtenAt`, `evidence`, optional `context`, `runId`, and `exactModelId`. Required string limits in that order are 128 / 256 / 160 / 12000 / 120 / 120 / 4000 characters for ID, subject, title, body, author, model, and evidence. Context is limited to 512 and exact model ID to 160 characters. Times are stored in UTC and displayed in the reader's host-local timezone with its offset. Author/model fields are attribution supplied by the writer, not cryptographic identity verification. Do not invent an exact model ID when the runtime does not expose one.

Notes are append-only: publish a new ID for revised commentary. Repeating an identical ID and payload is safe; changing its payload is rejected. The component displays the newest note with older revisions available below it. A context mismatch is flagged. Deck subjects use immutable deck IDs and a manifest hash context. Run notes must reference the exact session. Run-linked notes are removed through SQLite foreign-key cascade when that session is deleted; unrelated editorial notes remain.

The authored catalog in `src/DeckTester/notes/editorial.json` is imported transactionally and idempotently when the store first opens. Its 131 initial records cover 67 inspected deck versions, 35 pilot profiles, 13 chart explanations, eight observations for the latest inspected completed session, seven page notes, and one session summary. Missing deck/run references are skipped on other installations. This is authored seed content; new decks and runs need new notes supplied by an author. Existing matchup analysis is retained in its original table and is not retroactively attributed to this author.

Chart observations use the exact run ID plus metric title. They appear only for the full field of that run; selecting a matchup switches to general metric guidance. New runs also show the general guidance until specific observations are authored. The initial round-five observations use the existing chart's checkpoint aggregation and count contributing turn-end observations, not scheduled games. Results remain exploratory Forge diagnostics.

Validation: `dotnet run --project tests/AiNoteChecks/AiNoteChecks.csproj --no-restore` covers round-trip attribution, append-only revisions, subject isolation, required metadata, missing references, repeatable catalog imports, transactional rollback, and session deletion cleanup.
